# SmartBookmark Hub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 构建一个 Manifest V3 Chrome 扩展，提供「展示所选原生书签文件夹的可视化首页 + 书签优先的全局搜索 + 已有书签的智能治理」。

**Architecture:** 三层分离——React 页面层只调用 `src/core`；core 为纯 TS（无 DOM/React 依赖），所有 `chrome.*` 调用集中在 `backend.ts`（真实 ChromeBackend / 无 API 时 DemoBackend）；大对象存 IndexedDB，设置存 `chrome.storage.local`。长任务（扫描）跑在页面上下文并落盘续扫，Service Worker 只负责 omnibox / commands / contextMenus / 事件广播。

**Tech Stack:** Vite 8 · React 19 · TypeScript 5.9 · Tailwind CSS 4 · zustand 5 · pinyin-pro 3 · idb-keyval 6 · lucide-react · @tanstack/react-virtual · Vitest 5 · Playwright 1.65

**Spec:** [docs/SmartBookmark-Hub-技术方案.md](./SmartBookmark-Hub-技术方案.md)

## Global Constraints

- Manifest V3，`minimum_chrome_version: "116"`；SW 输出路径固定 `background.js`，`"type": "module"`
- 权限固定：`bookmarks, history, storage, tabs, search, favicon, contextMenus`；`optional_host_permissions: ["<all_urls>"]`
- omnibox 关键字固定 `bm`（manifest 声明，运行时不可改）
- `src/core/**` 禁止 import React、禁止直接引用 `document`/`window`（`yieldToBrowser` 内部需能力检测）
- 搜索排序恒定：书签 > 历史（score ≤ 40）> 网页（score = -1，永远最后）
- 死链判定：404/410/451 → `dead`；403/429/503 → `blocked`；其他 5xx → `error`；超时 → `timeout`；非 http(s) → `skipped`。**blocked/error/timeout 绝不进入删除预览**
- 删除必须：快照 → 回收站 → `chrome.bookmarks.remove*` → Toast 撤销
- 特殊文件夹 id `0/1/2/3` 永不出现在空文件夹报告，永不可删除
- 数据仅本地；无远程代码、无字体 CDN、无 telemetry
- 字体仅系统栈；配色令牌见 Spec §7.1，禁止默认灰
- 所有滚动区域自绘滚动条；所有异步操作具备 loading/成功/失败三态
- 提交信息使用中文前缀（`feat: `/`fix: `/`test: `/`chore: `）

## File Structure

见 Spec §8。每个文件单一职责：`url.ts` 只做归一化与 host 提取；`pinyin.ts` 只做带缓存的拼音转换；`search.ts` 只做索引与打分；`cleaner/pool.ts` 只做并发调度；`cleaner/deadLinks.ts` 只做单链接探测与分类；`cleaner/scan.ts` 只做编排与落盘；`trash.ts` 只做快照/恢复；`backend.ts` 是唯一 chrome 边界。
