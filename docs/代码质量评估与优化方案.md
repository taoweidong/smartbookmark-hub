# SmartBookmark Hub 代码质量评估与分阶段优化方案

> 版本 v1.0 ｜ 日期 2026-11-08 ｜ 基线：175 单测全绿 · tsc 0 error · build 通过 · E2E 37/37
> 评估方法：两名独立评审代理精读全部源码（core/background/scripts、ui/pages/config），主会话对全部 P1 级结论逐项复核源码后确认；P2 以下结论以代理审查为准并标注文件行号。
> 标注约定：**P0** 功能错误/安全漏洞（本次为 0）；**P1** 明确缺陷，会破坏真实场景功能；**P2** 应修复的质量/健壮性问题；**P3** 低风险瑕疵。

## Part A · 评估报告

### A1. 代码结构与分层合理性

**总体结论：优秀。** 三层架构（页面层 → core 纯逻辑层 → backend 适配层）执行严格：UI 层零直接 `chrome.*` 调用（全部经 `getBackend()`/`bookmarkService`/`store`）；background 仅做事件路由不做长任务；所有事件监听在模块顶层注册，符合 MV3 SW 生命周期要求。

| 级别 | 位置 | 问题 |
|---|---|---|
| P1 | `src/core/exportHtml.ts:58-67` | `downloadText` 在 core 层直接使用 `document.createElement/body`，违反「core 无 DOM 依赖」硬约束（技术方案 §3.1），导致导出逻辑无法在 SW/Node 复用 |
| P2 | `src/core/demoBackend.ts:172-183,209-211` | core 内直接 `window.open`（demo 后端情有可原，但污染 core 纯度） |
| P2 | `src/core/importHtml.ts:19` | `new DOMParser()` 为 core 对 DOM 的隐式运行时依赖（仅 options 页调用，可接受；需文档化偏差或注入解析器） |
| P3 | `src/core/backend.ts:2-3` | 静态 import 两个实现，Demo 数据连带进入 SW 产物 |
| P3 | `src/ui/styles.css:3-32` | `@theme` 调色板 token 未被任何工具类消费（实际颜色全走 `:root` 变量），属死配置 |

### A4. 错误与异常处理

**总体结论：主路径扎实。** `chromeBackend` 的 `invoke/invokeVoid` 统一检查 `chrome.runtime.lastError` 并 reject，storage/permissions 走 MV3 原生 Promise，无经典回调吞错；omnibox 有 requestToken 令牌防竞态；`store.mutate` 统一「成功 toast + refresh + 失败 toast」。问题集中在边缘路径的静默失败：

| 级别 | 位置 | 问题 |
|---|---|---|
| P1 | `src/core/demoBackend.ts:117-131` | `move` 先 `detach(id)` 再校验循环移动，throw 时节点已脱离原父且未挂回 → **demo 树永久损坏**（Chrome 端 move 失败不改状态，两端语义不一致） |
| P2 | `src/core/trash.ts:81-94` | `deleteWithUndo` 快照写入后逐个删除，中途失败无补偿：回收站包含「未实际删除」节点，恢复会产生重复 |
| P2 | `src/core/trash.ts:152-168` | `restoreBatch` 逐节点 recreate 无容错，任一失败即中断且批次保留 → 重试对已恢复部分重复创建 |
| P2 | `src/background/index.ts:119-127` | `sbh-save-page` 的 async IIFE 无 try/catch，create 失败产生 unhandled rejection 且徽标照常显示成功 |
| P2 | `src/pages/options/SettingsView.tsx:58,69,86` | `void store.updateSettings(...)` 丢弃 Promise 且 `updateSettings` 内部无 catch → 写设置失败完全静默 |
| P2 | `src/pages/options/TrashPanel.tsx:19-22,65-71,118-122` | `reload`/`purgeAll`/`purgeBatch` 无错误处理，读失败时静默显示「回收站为空」误导用户 |
| P3 | `src/background/index.ts:144` | `openHub` reject 时 `sendResponse` 永不调用，发送方挂起 |
| P3 | `src/core/cleaner/pool.ts:25-27` | worker 抛错整个池终止（结果留洞）；`onProgress` 回调抛异常会被当作 worker 失败 |
| P3 | `src/pages/options/SettingsView.tsx:54-56,161-188` | permission 查询初始 null 期间显示「未授予」误导；`.then` 均无 `.catch` |

### A6. 接口契约一致性

**总体结论：核心契约（Backend 17 方法签名、LinkHealth/SearchResult/ScanReport 数据形状）两端一致，tsc 强制保证。** 行为语义存在漂移：

| 级别 | 位置 | 问题 |
|---|---|---|
| P1 | `src/background/suggestions.ts:26-31` + `src/background/index.ts:90-98` | `parseSuggestionContent` 把任意非前缀文本当 `{kind:'url'}` 返回 → 用户在 omnibox 输入自由文本回车，原始文本被当 URL 传给 `tabs.create`，未走网页搜索兜底 |
| P2 | `src/core/demoBackend.ts:66-76` vs `chromeBackend.ts:126-131` | `onSettingsChanged` 契约不一致：chrome 端仅 `SETTINGS_KEY` 变化触发（含 remove），demo 端任意 key 的 set 都触发、remove 不触发 |
| P2 | `src/background/suggestions.ts:11` | web 建议通过正则反解写死的标题文案「在默认搜索引擎中搜索“…”」，与 `search.ts:199` 字符串强耦合，文案一改即静默失效 |
| P2 | `src/core/demoBackend.ts:148-158` vs `chromeBackend.ts:62` | demo `search` 过滤文件夹、空查询返回全部；chrome `bookmarks.search` 语义不同 |
| P3 | `src/core/demoBackend.ts:160-170` | `historySearch` 未按 `lastVisitTime` 降序（Chrome 按最近优先） |
| P3 | `src/core/demoBackend.ts:172-183` | `openUrl` 忽略 disposition；`webSearch` 与 chrome 端引擎选择行为漂移 |

### A7. 安全隐患

**总体结论：良好，无 P0。** 无 `dangerouslySetInnerHTML`/`innerHTML`；导出与 omnibox 描述经 `escapeHtml/escapeXml` 完整转义（`&` 先替换顺序正确）；导入用 DOMParser 白名单且仅接受 http/https；`<all_urls>` 为按需申请的可选权限；`window.open` 带 `noopener,noreferrer`；下载文件名程序生成无注入面。

| 级别 | 位置 | 问题 |
|---|---|---|
| P1 | `src/pages/options/BackupView.tsx:76-123` | JSON 恢复未校验备份内 `tags` 形状：`parseJsonBackup` 只验 `format`/`tree`，非法 `tags` 值（非数组/非字符串元素）会原样持久化进 settings，`BookmarkEditor.tsx:68` 对其 `for...of` 时 **TypeError → 每次启动白屏**（导入手改/损坏 JSON 即触发，且持久） |
| P3 | `public/manifest.json`（CSP） | `style-src 'unsafe-inline'` 与 `img-src http:` 可进一步收紧 |
| P3 | `src/core/chromeBackend.ts:80-98` | `openUrl` 未做 scheme 白名单（当前数据源安全，防御性建议） |
| P3 | `src/pages/newtab/BackgroundLayer.tsx:61-63` | 背景 URL 以 `url("…")` 拼 CSS，当前值仅来自本扩展生成的 dataURL，若未来写入其他 key 存在 CSS 逃逸面（备忘） |

### A8. 性能瓶颈

**总体结论：核心热路径已达标**（万级索引 <30ms、虚拟滚动、并发池 + 节流 + 缓存、`cache.entries` 已优化为 `keys`+`getMany` 批量读、搜索索引已预计算小写字段）。剩余：

| 级别 | 位置 | 问题 |
|---|---|---|
| P2 | `src/core/bookmarks.ts:143-145` | `removeMany` 逐 id 调 `remove` → 每次全树 structuredClone + findNode，O(N×M)：删除 500 条 = 500 次全树克隆 |
| P2 | `src/core/bookmarks.ts:71-93` | `collectFolders` 对每个文件夹独立递归 `countDeep`，嵌套链状树最坏 O(n²) |
| P2 | `src/pages/options/SettingsView.tsx:108-110` | Slider 拖动时每 step 触发一次 `saveSettings`（1 读 + 1 写 storage.local），高频写盘 |
| P3 | `src/core/bookmarks.ts:45-55`、`src/core/trash.ts:35-42` | `folderPathOf`/`hasSelectedAncestor` 每跳全树 `findNode`，O(深度×N) |
| P3 | `src/core/cleaner/duplicates.ts:110-115` | 桶内两两比较重复执行 `normalizeTitle/bigrams`；空标题+同 host 大桶退化 O(k²) |
| P3 | `src/core/store.ts:110-133` | 书签每次变更全量重建 entries（拼音有缓存缓解，已属可接受权衡） |

**Top 6 风险（全部已由主会话复核源码确认）：**
1. 恢复书签时 index 越界 → 真实 Chrome 撤销/回收站恢复直接失败（trash.ts）

6. `downloadText` DOM 越层 → core 无法在无 DOM 环境复用（exportHtml.ts）

## Part B · 分阶段优化方案

> 原则：**先加测试安全网，再动实现**；每阶段独立提交、独立验证、可单独回滚（`git revert <commit>`）；阶段内不混合行为修复与重构；所有阶段完成后跑全量 E2E 确认行为一致。

| 阶段 | 目标 | 涉及文件 | 验收标准 | 回滚边界 |
|---|---|---|---|---|
| **Phase 0 规范与基线** | 落地 agent.md 测试门禁；固化本报告与基线数据 | `agent.md`、本报告 | 文档入库；`npm run typecheck && npm run test` 全绿 | 纯文档，revert 无副作用 |
| **Phase 1 后端测试加固** | 为 store/cache/format 新建测试；扩充 trash/url/pool/deadLinks/search/scan 的异常与边界分支 | `src/core/*.test.ts`（纯新增，不改源码） | 新增 ≥40 例全绿；用例相互独立、可乱序重复执行 | 纯测试新增，revert 不影响行为 |
| **Phase 2 前端测试加固** | 补齐 hooks 与未测组件/页面的单测 | `src/ui/**/**.test.tsx`、`src/pages/**/**.test.tsx`（纯新增） | 新增 ≥25 例全绿 | 同上 |
| **Phase 3 core/background 修复** | 修复 Top6 中 5 项 + P2 批次语义/契约对齐/性能热点 | `trash.ts`、`demoBackend.ts`、`suggestions.ts`、`background/index.ts`、`exportHtml.ts`（downloadText 迁移至 `src/ui/download.ts`）、`bookmarks.ts`（removeMany/collectFolders） | 既有 175 例不回归；对行为有意变更处同步更新测试（move 校验、settingsChanged 事件、自由文本兜底）；新增测试验证 index clamp / move 先验后改 / 部分删除批次过滤 / 恢复补偿 | 每项修复独立小 commit；revert 单项不影响其他 |
| **Phase 4 前端修复** | JSON tags 校验、BackgroundLayer 三态补全、Slider 防抖提交、静默失败补 toast、Drawer Escape 连锁、CleanerView 竞态 | `BackupView.tsx`、`BackgroundLayer.tsx`、`SettingsView.tsx`、`TrashPanel.tsx`、`Drawer.tsx`、`CleanerView.tsx`、`importHtml.ts`（parseJsonBackup 校验） | Phase 2 新增测试全绿；损坏 JSON 导入不再产生持久化崩溃（新增回归测试）；solid 背景真实生效 | 同上 |
| **Phase 5 仓库卫生** | package.json 元数据（license/repository/engines）、GitHub Actions CI（typecheck+test 门禁，与 agent.md 规则呼应）、README 徽章数据更新 | `package.json`、`.github/workflows/ci.yml`、`README.md` | `npm run build` 通过；CI 配置语法合法（actionlint 或本地 node 校验） | 独立 commit，revert 无风险 |
| **Phase 6 终验** | 全量验证并更新报告终值 | 本报告 | tsc 0 error / 全部单测绿 / build 通过 / E2E 37 项全过；推送远端 | — |

**明确不做（本轮）**：HTML 导入进度条（大改，列入后续）、core 静态 import 改动态（构建收益存疑）、CSP 收紧（需实测 favicon 源）、duplicates 大桶上限（当前数据量无感知）、`noUncheckedIndexedAccess`（会产生大量连锁改动）。
