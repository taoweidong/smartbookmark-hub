## M1 · 用户反馈修复轮（2026-11-10，已交付，S1–S6 尚未开始）

用户在使用本地安装包时提出两条反馈，本轮先行修复，不改动 S1–S6 的计划内容。

### M1.1 反馈一：页面不随宽度自适应，部分区域白屏

**根因**：`popup.html` 用 `body { width:360px; height:560px }` 写死尺寸，且只考虑「工具栏弹窗」一种形态；`popup.html` 直接以标签页打开时仍是 360px 宽的窄条，右侧与下方留白即用户看到的「白屏」。

**修复**：
- `src/pages/popup/layout.ts`（新增）：`detectPopupLayout()` 用 `chrome.tabs.getCurrent()` 判定形态——有值说明当前文档位于标签页，无值即工具栏弹窗。不能用媒体查询判定：Chrome 弹窗的初始视口宽度就是上限 800px，`min-width` 媒体查询会把弹窗撑成 800px。
- `src/pages/popup/main.tsx`：在 `createRoot().render()` 之前 await 形态判定并写 `document.documentElement.dataset.sbhLayout`，避免首屏形态闪烁。
- `popup.html`：弹窗形态 `width:360px; height:auto; max-height:600px`；标签页形态 `width:100%; height:100%`。
- `src/pages/popup/App.tsx`：header/内容列统一 `max-w-[900px]` 居中（弹窗形态 360 宽不受影响；标签页形态避免按钮被拉到 500px 宽）；快捷动作 `grid-cols-2 sm:grid-cols-4`；最近列表 `flex-col sm:grid-cols-2 xl:grid-cols-3`；中部滚动区由 `flex-1`（basis 0）改 `flex-[1_1_auto]`，避免 auto 高度列把滚动区压成 0。

**红→绿**：新增 `src/pages/popup/layout.test.ts`（`detectPopupLayout` 四例：有 tab → `tab`；无 tab / 无 chrome API / 抛错 → `popup`；另加 popup.html 双形态 CSS 契约三例，删掉 `html { height:auto }` 即变红）；`scripts/e2e.mjs` 新增「弹窗识别为标签页形态」「弹窗铺满标签页宽度，无留白」「弹窗内容列收敛并居中」「弹窗 1280 无横向溢出」4 项断言。

### M1.2 反馈二：所有页面都应新开标签页，不要原地打开

**根因**：`Disposition` 允许 `'current'`，搜索结果/书签卡片/omnibox 都存在原地覆盖当前页签的分支；而管理台用 `chrome.runtime.openOptionsPage()` 打开时会复用已有的 options 标签页，把用户正在填的面板刷新掉。

**修复**：
- `src/core/types.ts`：`Disposition` 收窄为 `'newTab' | 'newWindow'`，`'current'` 从类型层面删除，结构上不可能原地打开。
- `src/core/chromeBackend.ts`：`openUrl` 只保留 `chrome.windows.create` / `chrome.tabs.create`；`webSearch` 恒走 `chrome.search.query({ disposition:'NEW_TAB' })`；`openOptions` 改 `chrome.tabs.create({ url: options.html, active:true })`。
- `src/background/index.ts`：`openHub` 恒 `chrome.tabs.create`；omnibox 自由文本走 `webSearch`，URL 走 `openUrl(url,'newTab')`。
- `src/ui/openWithFeedback.ts`、`src/ui/hooks/useSearch.ts`、`src/ui/components/{ResultList,SearchBox,BookmarkCard}.tsx`、`src/pages/newtab/Dashboard.tsx`、`src/pages/popup/App.tsx`：调用点统一到新标签页语义，提示文案改为「Enter 新标签页打开」。

**红→绿**：`src/core/chromeBackend.test.ts` 新增「只允许新标签页/新窗口」「不再更新当前标签」「webSearch 一律新标签页」「openOptions 不复用已有标签页」；`src/background/index.test.ts` 同步 omnibox/openHub 断言；`scripts/e2e.mjs` 新增「Enter 一律新标签页打开书签」「原页签未被原地替换」「首页书签在新标签页打开」「首页未被原地替换」「管理台在新标签页打开」5 项断言。

## M2 · 顶部空间与概览文字收敛轮（2026-11-11，已交付）

用户反馈：顶部菜单占空间过大；「夜深了 11 月 11 日 · 周三 / 「常用」展示 6 个文件夹、381 条书签。其余 823 条随时用搜索找回。」两段文字加统计四卡把书签内容压到首屏下半部，显示效率低。本轮提前交付 S1 的首屏空间目标。

### M2.1 根因（真实 Chromium 量取，1224 条书签 / 20 文件夹 / 选中 6 个）

- 顶部三层 band：品牌+搜索行 68px、页签行 37px、视图设置行 47px（窄屏换行后 83/118px），合计 153px（1024/800 为 189px、560 为 225px）。
- 问候+日期独占一行、页签摘要独占一行，共 53px；其下统计四卡再占约 86px。
- 结果：1280×900 首张卡片 y=389，首屏仅 4 行 16 张完整卡片；560 宽首卡 y=563。

### M2.2 改动

- **两层顶部 + 可折叠视图栏**：`src/pages/newtab/App.tsx` 顶部收敛为「品牌+搜索+主题+管理台」与「页签+视图齿轮+选择文件夹」两行；视图设置（布局/卡片/排序/每组数量/背景/主色/统计/重置）移入第三层 band，仅展开时渲染。展开态写入 `settings.dashboard.viewBarOpen`（`src/core/types.ts`、`src/core/settings.ts` 默认 `false` 并做形状防御），刷新后保持。
- **主操作不离场**：「选择文件夹」保留在页签行右侧恒可见；`DisplayControls` 删除该按钮与 `onPickFolders` prop，避免双入口。
- **单行概览条**：问候+日期合并进唯一 `h1`；页签摘要（`常用 6 文件夹 · 384 书签`）、「其余 N 条 ⌘K」聚焦搜索 chip、四个行内迷你统计（书签总数/文件夹/近 7 天/链接健康度）与「仅存本机」chip 同排 flex-wrap，容器 `role="group" aria-label="首页概览"` + `data-sbh-context` 供量取与 E2E。统计四卡 `StatTile` 在首页下线（options 清理页仍复用），`showStats` 语义不变。
